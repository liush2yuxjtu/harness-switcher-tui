## 问题与证据

用户希望在终端中体验不同 agent harness 的统一操作，切换观察时后台任务不应被取消，并能区分真实运行、离线模拟和失败。

现有 demo 已实现 Pi / Cline 的独立任务切换，但尚无经审批的 intent、spec、plan，也无独立代码审查记录；目录尚未初始化 Git。不能将已有实现反向视为设计已批准。

已读取的本地证据：
- `../README.md`：现有交互、适配器、临时工作区与依赖风险说明。
- `../test-results/final-validation.json`：记录类型检查、14/14 测试、离线 PTY 通过；最后真实 smoke 返回 HTTP 401 `auth_unavailable`。
- 上述验收记录由实现子代理生成；本次 Capture 仅读取，未重新运行或独立复核全部测试。

当前真实 CPA 调用受上游认证错误影响。错误信息不足以确认完整根因；认证是否已经恢复未知。较早真实测试通过不代表当前仍可用。

## 期望结果

- 用户在纯终端中选择至少两种不同 harness 并提交任务。
- 任务后台并发执行，切换观察不影响其他任务。
- 用户能观察流式输出、状态和错误，取消指定任务并安全退出。
- 真实模式使用实际 HarnessAgent；离线模拟明确标记，不能冒充真实结果。
- 通过当前可复核证据判断可用范围，明确认证和依赖风险。

## 成功信号

- 在两个不同 harness 中启动任务，切换后两者继续执行，切回可查看各自结果。
- 指定任务取消不影响其他任务；退出恢复终端并完成资源清理。
- CPA 可用时，两种 harness 均有本轮真实文本流和文件读写证据。
- CPA 不可用时，显示明确认证错误，不静默切 provider、模型或离线模式。
- 需求可映射到测试；未验证能力和依赖告警有明确记录。
